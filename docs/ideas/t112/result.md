# T1.12 spike digests: result

**Verdict: built and gated, ships as an opt-in preset (`digest`), not a default. The fired-output reduction gate passes; the excess re-fetch gate is NOT measured; real coding traces almost never fire a digest.**

## What exists
- `scripts/digest.py`: the 11 encoders (#118 #121 #122 #132 #133 #137 #220 #314 #411 #606 #703), generated from the gate prototypes by `scripts/gen_digest.py` (regeneration is byte-identical). `digest(text, command)` keeps a result only if it removes >= 40% of the characters (kill gate), is total, and never grows the text.
- Preset `digest` (`ctxprune_core.PRESETS`, also `CTXPRUNE_PRESET=digest`, `ctxprune install --preset digest`): safe lossless stage + digests, no model. The ORIGINAL output is written byte for byte to the recover store (`~/.cache/ctxprune/out/<sha12>.txt`) and the digested text ends with `[ctxprune digest #121,...: this output was condensed on purpose; the original is saved at <path> ...]`. No saved original = no digest. File views and errors are never digested. Off: `CTXPRUNE_DIGEST=0` or `CTXPRUNE_OFF=1`.
- Tests: `scripts/test_digest.py` (preset, exact original on disk, disclosure, safe preset untouched, totality), gate `run.py` for the 11 ids: 11 pass.

## Numbers
Gate fixtures (mean char reduction on shrinking fixtures): #606 -99, #132 -94, #122 -93, #314 -90, #121 -89, #133 -88, #411 -87, #703 -72, #220 -71, #118 -31, #137 -22. #118 and #137 are under the 40% gate on their own fixtures: they only fire when part of a larger output that reaches 40% overall.

Screen on 11,583 real tool outputs >= 1500 chars (cc_usage, agent_samples, local_eval, usage_v1, squeez; 133 MB, 15 s CPU, nothing slow):
- 9 of 11 digests fired 0 times.
- #118 fired on 419 (12% mean reduction, below the gate); #132 on 103 (14%).
- With the 40% gate: 3 outputs fired (0.03%): #132 x2, 79% (20.9k -> 4.4k chars), #118 x1, 40%. Share of all tool-output characters saved: ~0.016%.

## Not measured (gate item missing)
Excess re-fetch rate on fired items: n=3 fired outputs in the captured corpora, so no replay is meaningful; no GPU reader job was run. The re-fetch claim stays open until a corpus with lockfile/registry/compiler-flood outputs exists.

## Conclusion
The digests are real and large where they apply (70-99% on spikes) but spikes are rare in coding traces, so `digest` is not worth making default; it is a workload preset for devops / dependency / C++ / ML-training sessions. Next step if pursued: collect a spike corpus (git diff of lockfiles, `npm view --json`, g++ errors, terraform plans) to measure re-fetch.

## Distribution plan
Users: people on Claude Code, Hermes, Pi, OpenCode, dsh, Codex whose work is infra, dependency bumps, C++ or training logs. Seam: the existing preset switch (`ctxprune install <agent> --preset digest`, `CTXPRUNE_PRESET`), the same PreToolUse/PostToolUse hook path as `safe`; `scripts/digest.py` is added to `glue.SAFE_MODULES` so plugin bundles carry it (bundles are regenerated by `ctxprune.bundle`, not hand-copied). Document under the README preset table when released; no new channel.
