# L4.3 MCP gateway (`ctxprune mcp-gateway --config FILE`)

Verdict: static-schema kill gate PASSES (>=85%); discovery-turn half of the gate and the live-client completion test are NOT measured.

- Static schema: 3 meta-tools = 598 chars JSON vs 7,994 chars for one real server's 10 tools
  (`ctxprune-v2/runbook/.mcp_tools.json`) = **92.5% reduction** (worst case: one small server; more backends only raise it).
  Synthetic 3x12-tool backends in `tests/test_mcp_gateway.py` also asserted >=85%. Measured in chars of JSON, not model tokens.
- `list_tools` returns one line per tool (`server/tool: first sentence (required args)`), ~790 chars for those 10 tools, on demand.
- `call_tool` output goes through the lossless `safe` pipeline (text content only; results with `structuredContent` untouched).
- Discovery cost: list_tools (+ optional describe_tool) before the first call = 1-2 extra turns; gate says <=1, so it is borderline until
  measured with a real client. Not measured: GitHub/Playwright/Notion in Cursor/Codex/OpenCode, task completion rate, round-trip of compressed outputs.
- Limits: stdio backends only, one request at a time (lock), no timeouts, backend stderr passes through.

Distribution (METHODOLOGY 13): users of Cursor/Codex/OpenCode/Claude Desktop (clients without deferred tool loading) replace N
`mcpServers` entries with one `ctxprune mcp-gateway --config ...` entry; reached via the existing `ctxprune mcp` MCP seam,
README/PACKAGE install docs and the MCP registry `server.json` listing.
